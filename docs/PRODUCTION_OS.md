# Живой Сбой — производственная система

Рабочая спецификация для ежемесячного выпуска из 20 артистов и 60 песен.

## Базовая математика

- 20 артистов.
- 3 песни на артиста.
- 60 номеров.
- 3 вечерние волны по 20 номеров.
- 85–95 минут на одну волну.
- 5 постоянных виртуальных сцен.
- 5 номеров уровня A, 15 уровня B, 40 уровня C.

## Двухмесячный конвейер

В любой момент одновременно существуют три выпуска:

- N выходит и анализируется;
- N+1 монтируется и проходит QC;
- N+2 находится на стадии песен, сценария и визуальных брифов.

Без этого буфера ежемесячный выпуск из 60 новых песен неустойчив.

## Матрица 20×3

Каждая строка — артист. Колонки:

1. Песня «Я».
2. Песня «Сбой».
3. Песня «Отзвук».

Обязательные поля трека:

- ID выпуска, артиста и волны;
- рабочее и финальное название;
- WAV master 48 kHz / 24 bit;
- instrumental;
- текст и редакторская версия;
- длительность и festival cut;
- BPM, тональность, размер;
- музыкальный хук с таймкодом;
- эмоциональная функция;
- сюжетное изменение;
- сцена;
- визуальный уровень A/B/C;
- сценарий вступления;
- фраза ведущего после песни;
- права, источники и использованные сервисы;
- статусы аудио, видео, субтитров и QC.

## Именование файлов

Шаблон:

`JS{issue}_{artistNumber}_{wave}_{asset}_{version}.{ext}`

Примеры:

- `JS01_01_W1_master_v03.wav`
- `JS01_01_W1_instrumental_v02.wav`
- `JS01_01_W1_lyrics_v04.txt`
- `JS01_01_W1_visualBrief_v02.md`
- `JS01_01_W1_showMaster_v05.mov`
- `JS01_01_W1_vertical15_v02.mp4`
- `JS01_01_W1_subtitles_ru_v03.srt`

Запрещены названия `final-final2`, `новая версия`, `точно готово`.

## Статусы

`ожидается → демо → редактура → мастер → визуальный бриф → аниматик → производство → монтаж → QC → готово → запланировано → опубликовано`

Назад статус переводится только с комментарием о причине.

## Визуальные уровни

### A — флагман

- 5 песен на фестиваль;
- 4–7 производственных дней на номер;
- индивидуальная режиссура;
- 8–15 планов;
- сложная сценическая трансформация;
- короткий качественный липсинк;
- минимум один кадр, пригодный для постера;
- один вирусный фрагмент 10–20 секунд.

### B — персонажное выступление

- 15 песен;
- 1–3 дня;
- 3–6 планов;
- короткий липсинк в ключевых строках;
- фирменный реквизит;
- одна драматическая перемена света или пространства.

### C — графический номер

- 40 песен;
- модульная сборка;
- 2.5D-портрет;
- кинетическая типографика;
- параллакс;
- 3–5 музыкальных циклов;
- крупные предметные планы;
- без попытки изображать непрерывное реалистичное пение.

## Пакет персонажа

Минимум до производства номера:

- основной портрет 16:9;
- вертикальный портрет 9:16;
- фронтальный крупный план;
- три эмоции;
- нейтральный рот и базовые фонемы;
- полный силуэт;
- фирменный реквизит отдельно;
- палитра;
- знак/монограмма;
- правила света;
- список визуальных запретов.

## Пакет одной песни

- мастер;
- инструментал;
- текст;
- festival cut 2:30–3:10;
- 30-секундный хук;
- 15-секундный вертикальный хук;
- обложка;
- видеомастер 16:9;
- вертикальная версия;
- SRT на русском;
- текстовое описание;
- прозрачный disclosure об использовании ИИ;
- карточка прав.

## Сценарий перехода

Каждый переход содержит не больше двух элементов:

- одна мысль;
- одна шутка;
- одно сообщение из зала;
- один сюжетный факт;
- одно предупреждение о визуальных эффектах.

Продолжительность обычного перехода: 12–35 секунд. Большая интерлюдия после блока из четырёх песен: 60–100 секунд.

## Безопасный реактивный ведущий

80% реплик записываются заранее. До 20% могут создаваться во время премьеры.

Живая цепочка:

1. Получение сообщений из разрешённого источника.
2. Фильтрация персональных данных, оскорблений и опасных тем.
3. Генерация трёх вариантов реплики.
4. Человеческое подтверждение.
5. Синтез голоса.
6. Вывод в эфир через OBS.

Полностью автономный микрофон запрещён.

## Ежемесячный цикл

### Неделя 1 — музыка

- приём 60 треков;
- редактура;
- festival cuts;
- проверка контраста;
- распределение по волнам;
- выбор уровней A/B/C.

### Неделя 2 — сценарий

- трёхпесенные арки;
- порядок номеров;
- переходы;
- рубрики;
- голос ведущего;
- аниматики;
- технический хронометраж.

### Неделя 3 — производство

- флагманские номера;
- персонажные номера;
- графические сборки;
- липсинк;
- титры;
- вертикальные тизеры.

### Неделя 4 — выпуск

- общий монтаж;
- выравнивание аудио;

- репетиция OBS;
- трейлеры;
- три премьеры;
- разбор аналитики.

## Техническая архитектура

### Публичный слой

- Next.js на Vercel;
- страницы выпусков `/01`, `/02`;
- каталог артистов;
- программа;
- интерактивный второй экран;
- архив.

### Данные

- Supabase Postgres;
- Supabase Auth только там, где действительно нужен профиль;
- Realtime Broadcast для реакций;
- Presence только для числа подключённых зрителей;
- RLS для голосований и приватной студии.

### Видео

- YouTube Premiere как основной публичный эфир;
- Cloudflare Stream как резерв и собственный архив;
- Cloudflare R2 для исходников, изображений и прокси;
- Vercel и Supabase Storage не использовать как основную доставку тяжёлых видео.

### VPS

Docker Compose:

- n8n;
- FastAPI worker;
- Redis;
- FFmpeg;
- Caddy;
- Uptime Kuma;
- Restic.

Задачи VPS:

- очередь;
- сборка прокси;
- нарезка 16:9 и 9:16;
- нормализация метаданных;
- проверка длительности и кодеков;
- загрузка;
- отчёты;
- резервные копии.

Без GPU VPS не используется для тяжёлого AI-видео и 3D-рендера.

Минимальные роли, даже если часть выполняет один человек:

- шоураннер и финальное решение;
- музыкальный редактор/A&R;
- сценарист мира;
- визуальный режиссёр;
- motion/3D;
- монтажёр;
- звукорежиссёр выпуска;
- технический продюсер;
- модератор премьеры;

ИИ может ускорять роли, но финальное подтверждение музыки, сценария, лица, голоса и публикации должно принадлежать назначенному человеку.

## QC

### Музыка

- нет клиппинга;
- согласована громкость между номерами;
- текст соответствует утверждённой версии;
- начало и конец не обрезаны;
- инструментал сохранён.

### Видео

- персонаж узнаваем;
- нет лишних конечностей и сломанной анатомии;
- рот не двигается бессмысленно;
- нет случайных надписей и логотипов;
- свет не разрушает силуэт;
- соблюдены safe zones 16:9 и 9:16;
- вспышки отмечены предупреждением.

### Сценарий

- имя и факты канона верны;
- шутка не унижает слабость;
- переход не пересказывает песню;
- нет подражания реальному артисту;
- мысль понятна без лор-справочника.

### Публикация

- субтитры;
- описание;
- disclosure;
- обложка;
- таймкоды;
- права;
- резервный файл;
- проверена премьера и чат-модерация.

## Реестр прав

Для каждого файла фиксируются:

- автор/редактор;
- использованный сервис и модель;
- дата генерации;
- версия условий на дату генерации;
- разрешение на коммерческое использование;
- исходные материалы;
- согласия на голос и внешность;
- отсутствие запрещённой имитации;
- итоговый ответственный редактор.

## Метрики

Главные:

- возврат зрителей между выпусками;
- среднее время просмотра каждой волны;
- досмотры после четвёртого блока;
- конверсия тизер → напоминание;
- доля участвующих в реакции или голосовании;
- распределение интереса между двадцатью героями;
- стоимость одного готового номера каждого уровня;
- процент переделок после QC.

Не оптимизировать проект только по лайкам и просмотрам одного вирусного персонажа.

## Критерий готовности фестиваля

Выпуск готов не тогда, когда сгенерированы все файлы, а когда:

- три волны имеют самостоятельную драматургию;
- каждый герой меняется между первой и третьей песней;
- нет двух соседних номеров одной температуры;
- звук воспринимается как единая программа;
- минимум пять моментов хочется пересмотреть;
- финал отвечает на вопрос выпуска и открывает следующий.
